2. RESUMEN TECNICO GENERAL
===============================================================================

NAVI Herramientas & Activos es un sistema modular desarrollado con .NET 8,
Blazor, SQL Server, Docker y MinIO. Su objetivo tecnico es administrar
herramientas y activos fijos desde una consola web administrativa y una PWA
movil.

Componentes principales:

1. API Backend:
   - Proyecto: Navi.ToolsAssets.Api.
   - Expone endpoints REST.
   - Gestiona reglas de negocio.
   - Consulta y modifica SQL Server.
   - Integra documentos con MinIO.
   - Expone Swagger en desarrollo.
   - Usa Hangfire para procesos de fondo.

2. Admin Web:
   - Proyecto: Navi.ToolsAssets.Admin.
   - Blazor Server.
   - Consola administrativa de inventario, configuracion, asignacion,
     reportes, documentos, toma fisica, conciliacion y backups.

3. Mobile PWA:
   - Proyecto: Navi.ToolsAssets.MobilePwa.
   - Blazor WebAssembly / PWA.
   - Uso operativo desde celular o tablet.

4. Base de datos:
   - SQL Server 2022 en Docker.
   - Base local principal: NaviToolsAssetsDb.

5. Almacenamiento documental:
   - MinIO.
   - Bucket esperado: navi-tools-documents.

6. Procesos:
   - Hangfire.
   - Pensado para importaciones, backups, conciliaciones y procesos largos.

5. TECNOLOGIAS Y JUSTIFICACION
===============================================================================

.NET 8:
- Plataforma moderna, estable y compatible con API, Blazor y EF Core.
- Permite arquitectura limpia, DI, middleware, configuracion por ambientes.

ASP.NET Core Web API:
- Exposicion de endpoints REST.
- Integracion con Swagger, autorizacion, DI y middlewares.

Blazor Server:
- Permite construir Admin Web con C# y Razor.
- Ideal para consola administrativa interna.
- Reduce dependencia de frameworks JS externos.

Blazor WebAssembly PWA:
- Permite experiencia movil instalable.
- Reutiliza C# y modelos.
- Adecuada para tecnico en campo o tablet.

SQL Server:
- Motor robusto y compatible con entornos Microsoft.
- Soporta backups .bak.
- Facil integracion con EF Core y herramientas Microsoft.

Docker:
- Permite ambientes reproducibles.
- Facilita SQL Server y MinIO locales.
- Permite crear varios contenedores de base de datos para pruebas.

MinIO:
- Almacenamiento de documentos tipo S3.
- Evita guardar archivos pesados directamente en SQL Server.

Hangfire:
- Permite procesos en segundo plano.
- Util para backups, importaciones, conciliaciones y tareas programadas.

Swagger:
- Facilita pruebas de endpoints durante desarrollo.

6. MODULOS TECNICOS
===============================================================================

Inventario:
- Gestiona ToolAssets.
- Controla codigo, nombre, serial, marca, tipo, categoria, estado, sede,
  ubicacion, estanteria, responsable y trazabilidad.

Disponible y ubicacion:
- Cambia estado operativo y fisico.
- Cambia sede, almacen y ubicacion exacta.
- Debe registrar eventos de ciclo de vida.

Asignacion:
- Asigna activos a responsables.
- Registra regreso a almacen o taller.
- Maneja aprobacion, rechazo y trazabilidad.

Prestamos:
- Registra prestamos temporales.
- Controla entrega, reintegro, responsable, estado y observaciones.

Hoja de vida tecnica:
- Consolida historia del activo.
- Incluye documentos, accesorios, mantenimientos, asignaciones, eventos y
  practicas seguras.

Documentos:
- Carga, consulta y descarga evidencias.
- Integra con MinIO.
- Asocia documentos a herramienta o proceso.

Mantenimiento:
- Programa, inicia, completa y cancela mantenimientos.
- Registra proveedor, tecnico, costo, actividades, resultado y evidencia.

Compras:
- Gestiona solicitudes, aprobacion, rechazo, cierre y marca enviada a
  sistema externo.

Toma fisica:
- Permite campañas de inventario fisico.
- Registra encontrados, no encontrados y reportados no registrados.

Conciliacion:
- Compara datos internos contra datos fisicos o externos.
- Registra diferencias y acciones.

Reportes:
- Genera vistas ejecutivas y operativas.
- Debe evolucionar a exportacion Excel y PDF formal.

Configuracion:
- Zonas, sedes, ubicaciones, responsables, tipos, categorias, estados,
  usuarios, roles, permisos y parametros.

Sincronizacion y exportacion:
- Debe manejar backup, subida, descarga, verificacion, importacion y, a futuro,
  operaciones por compañia activa.

Carpeta:

Formatos esperados:
- .bak
- .bacpac
- .zip
- .7z

Flujo seguro:
1. Crear backup antes de cambios.
2. Verificar backup.
3. Guardar backup local.
4. Ejecutar operacion.
5. Validar resultado.
6. Crear backup final.

Reglas:
- No borrar datos sin backup.
- No restaurar sobre base principal sin probar primero en base temporal.
- No subir backups a Git.
- Registrar auditoria de backup.
- Proteger operaciones con contraseña personal.

El modulo Sincronizacion y Exportacion debe evolucionar para operar por base
activa cuando exista multicompañia.

13. SEGURIDAD ACTUAL Y EVOLUCION
===============================================================================

La seguridad actual debe considerarse MVP local.

Elementos actuales:
- Usuarios.
- Roles.
- Permisos.
- PermissionGuard en UI.
- RequirePermission en API.
- Sesiones Admin/Mobile.
- Alcance por sede y responsable en algunos flujos.

Riesgos:
- Confianza en headers enviados por cliente.
- Falta de autenticacion robusta obligatoria en API.
- Necesidad de JWT o cookie segura.
- Necesidad de claims firmados.
- Necesidad de PasswordHasher.
- Necesidad de proteger Swagger y Hangfire.
- Necesidad de mover secretos fuera de appsettings.
- Necesidad de validar tenant desde servidor.

Arquitectura futura:
Login -> token firmado -> claims -> API valida token -> API valida tenant ->
API valida permiso -> API ejecuta accion.

El presente documento debe ser modificado cuando se implemente esta nueva
arquitectura de seguridad.
